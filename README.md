## Overview

A 3-MCU IoT system with environmental sensing, audio processing, and Bluetooth speaker — all generated from a single visual design by CircuitOS Studio.

Every file in this repository was **deterministically generated** from a visual circuit design
using [CircuitOS Studio](https://circuitos.dev). The same design will always produce identical
output — no randomness, no AI hallucination, no architectural drift.

## What This System Does

- Read data from 5 sensor(s)
- Communicate between 3 microcontrollers via TCP, SPI, HTTP, BLUETOOTH, I2S, REST_API, I2C
- Stream sensor data to backend server
- Display data on web dashboard


## Architecture

CircuitOS enforces a strict **4-layer architecture** with **14 Gang of Four design patterns**
applied automatically. No ESP-IDF API is ever exposed above the PAL layer — the entire
application stack is portable to any RTOS by swapping only the PAL implementation.

```
┌─────────────────────────────────────────────────────────────────┐
│                      Application Layer                          │
│  State machines, task orchestration, business logic             │
│  Patterns: Observer, Strategy, Command, Template Method         │
├─────────────────────────────────────────────────────────────────┤
│                     Middleware Layer                             │
│  Event bus, pub/sub, telemetry sender, data processing          │
│  Patterns: Mediator, Chain of Responsibility, Decorator         │
├─────────────────────────────────────────────────────────────────┤
│                   Component Drivers                             │
│  Sensor/actuator C++ classes with clean interfaces              │
│  Patterns: Adapter, Facade, Factory, Composite, Builder         │
├─────────────────────────────────────────────────────────────────┤
│                  OSAL (OS Abstraction)                          │
│  Tasks, timers, mutexes, queues, logging, delays                │
│  Patterns: Singleton, Proxy                                     │
├─────────────────────────────────────────────────────────────────┤
│                  PAL (Platform Abstraction)                     │
│  I2C, SPI, GPIO, UART, ADC, PWM, I2S — wraps ESP-IDF           │
│  ⚠️  ONLY layer that touches hardware SDK                       │
├─────────────────────────────────────────────────────────────────┤

```

## Getting Started

### Prerequisites

| Tool | Version | Purpose |
|------|---------|---------|
| [ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/get-started/) | v5.1+ | Firmware build system |
| Python | 3.10+ | Backend API server |
| Node.js | 18+ | Frontend dashboard |
| USB Cable | — | Firmware flashing |

### Build & Flash Firmware

#### theSpeaker (ESP32)

```bash
cd device_theSpeaker
idf.py set-target esp32
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor
```

#### environment (ESP32-C3)

```bash
cd device_environment
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor
```

#### motor_n_mike (ESP32C3)

```bash
cd device_motor_n_mike
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor
```


### Run Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python main.py
# Backend starts on http://localhost:8000
```

### Run Frontend

```bash
cd frontend
npm install
npm run dev
# Dashboard opens at http://localhost:3000
```

### One-Click Scripts

```bash
./scripts/start_backend.sh    # Start the backend server
./scripts/start_frontend.sh   # Start the frontend dashboard
./scripts/build_device.sh     # Build all firmware targets
./scripts/flash_device.sh     # Flash firmware to connected board
```

## Enabling CI/CD

A GitHub Actions workflow is included in `ci/build.yml`. To enable automatic builds:

```bash
mkdir -p .github/workflows
cp ci/build.yml .github/workflows/build.yml
git add .github && git commit -m "Enable CI" && git push
```

> **Note:** Pushing workflow files requires a GitHub token with the `workflow` scope.

## Why CircuitOS — Not AI?

| | AI Code Generation | CircuitOS Studio |
|---|---|---|
| **Consistency** | Different output every run | Deterministic — same design = same code |
| **Architecture** | Must know to ask for it | Enforced 4-layer (PAL/OSAL/MW/App) |
| **Multi-MCU** | Can't coordinate across boards | DataFlow Engine syncs all MCUs |
| **Design patterns** | Only if prompted correctly | 14 GoF patterns auto-applied |
| **Pin assignments** | May hallucinate | Verified from tested board registry |
| **Protocol contracts** | Drift across iterations | Single source of truth |
| **Portability** | Tightly coupled to SDK | Swap PAL → run on any RTOS |
| **Reproducibility** | Never the same twice | 100% identical every time |
