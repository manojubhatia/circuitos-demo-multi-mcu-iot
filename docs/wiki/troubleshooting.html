Troubleshooting

Common issues and solutions for building, flashing, and running this project.

Build Issues

ESP-IDF build fails with missing component

Cause: Component not declared in idf_component.yml

Solution:

Run: idf.py add-dependency

Communication Issues

SPI device returns all zeros/0xFF

Protocol: SPI

Cause: CS pin wrong or clock polarity mismatch

Solution: Verify CS is active-low and toggling. Check CPOL/CPHA settings match device datasheet.

HTTP POST to backend fails

Protocol: HTTP

Cause: WiFi not connected or backend unreachable

Solution: Verify WiFi credentials. Check backend URL is accessible from device network.

BLE device not discoverable

Protocol: Bluetooth

Cause: Advertising not started or wrong parameters

Solution: Ensure BLE advertising is started. Check UUID and service parameters.

I2S audio has static or silence

Protocol: I2S

Cause: Wrong sample rate, bit depth, or pin configuration

Solution: Verify sample rate matches audio source. Check BCLK, WS, DIN/DOUT pin assignments.

I2C device not responding

Protocol: I2C

Cause: Wrong address, missing pull-ups, or wiring issue

Solution: Run I2C scan. Ensure SDA/SCL have 4.7kΩ pull-ups to 3.3V. Check address (7-bit vs 8-bit).

Hardware Issues

Board not booting (theSpeaker, environment, motor_n_mike)

Symptom: No serial output, LED not blinking

Check: Verify power supply voltage (3.3V/5V) and current capacity

Fix: Use USB port or power supply providing adequate current (500mA+ per board)

Sensor readings invalid (aht10)

Symptom: Always returns 0, NaN, or unrealistic values

Check: Verify wiring matches pin assignments in generated code

Fix: Cross-check GPIO numbers in source code with physical connections. Use multimeter to verify 3.3V on VCC.
