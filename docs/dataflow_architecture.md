## How It Works

### Sender MCU (Data Producer)

1. **Sensor Task** reads hardware sensors periodically (e.g., AHT10 over I2C)
2. Values are stored in static variables registered with `dataflow_register_variable()`
3. After each read, `dataflow_notify_changed()` pushes the value to the exchange queue
4. **Exchange Task** (FreeRTOS, Core 1) dequeues items, builds packets with:
   - Magic bytes (0xDF 0x01) for framing
   - Variable ID string for routing
   - CRC16 checksum for integrity
5. Packets are sent via the configured transport (`dataflow_wifi_send()`, etc.)

### Receiver MCU (Data Consumer)

1. **Transport Layer** (TCP server/client) receives raw bytes
2. **Exchange Task** validates magic bytes and checksum
3. Variable ID is extracted and routed to the appropriate handler:
   - If a display is bound: `display_ui_dataflow_update()` maps the variable to an LVGL widget
   - If a callback is registered: `dataflow_display_callback_t` is invoked
   - Value is stored in the local variable registry

### Key Files

| `dataflow_wifi.h/c` | TCP socket transport (server or client mode) |
